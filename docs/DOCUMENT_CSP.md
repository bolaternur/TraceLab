# Политика скриптов активного интерфейса

Видимые публичные страницы, статическая оболочка `/workspace`, учебный пример и offline capture получают CSP с `script-src 'self'` и SHA-256 точного скрипта раннего выбора темы. Произвольные inline-скрипты и HTML-обработчики событий не разрешены. Изменение загрузчика темы автоматически меняет ожидаемый hash.

Динамические страницы `/auth`, `/account`, `/join`, `/onboarding` и `/workspace/model/*` получают свежий случайный nonce из `src/proxy.ts`. Переданные клиентом nonce/CSP заменяются сервером. Одинаковое значение передаётся Next для серверного рендера и в заголовок ответа; собственный theme bootstrap также помечен nonce. Страницы уже используют динамический рендеринг.

`unsafe-eval` остаётся только для разработки Next. `style-src 'unsafe-inline'` сохранён: граф, Three.js и React задают координаты/размеры через динамические стили. Это не разрешение произвольных JavaScript-обработчиков. Внешние Framer runtime и CDN-скрипты не подключаются.

Проверено локально: HTTP 200 статической оболочки и формы восстановления, hash/nonce в реальных заголовках, отсутствие `unsafe-inline` в их `script-src`, nonce у загрузочных скриптов Next; браузерная гидратация и смена темы работают без ошибок CSP. Модульная проверка подтверждает замену присланного nonce и уникальность последовательных ответов.

Граница: общий fallback header для неактивных legacy/прочих маршрутов пока сохраняет прежнюю политику совместимости. Эта работа не объявляет полный аудит XSS завершённым и не заменяет безопасный рендер строк, проверку входных данных и серверные ограничения доступа.
