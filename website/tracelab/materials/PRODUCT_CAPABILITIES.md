# TraceLab: фактические возможности

Проверка 28 сентября 2026. Это начальный аудит по коду и выполненным проверкам,
не заключение о готовности к production. Полный перечень требований ещё не реализован.

| Возможность | Статус | Доказательство / ограничение |
| --- | --- | --- |
| Capture, итерации, тесты, решения и связи | Работает частично | Реальные таблицы и действия; запись Capture не атомарна |
| Авторизация паролем, сессии, роли | Работает частично | scrypt, хеши токенов, membership checks; нет email verification/reset/rate limiting |

| AI | Требует внешней настройки | По умолчанию disabled; fake режим только для демонстрации |

## Что TraceLab умеет

Сохранять инженерные события, авторские пояснения, тесты и решения в связанных
таблицах. Проверять членство в команде при доступе к её рабочему пространству,
медиа и экспорту. Показывать граф и хронологию. Сохранять локальную очередь Capture.
Смена языка имеет общий компонент на публичной странице, desktop/mobile и в Settings.

## Что работает частично

Наличие функции в коде не означает её эксплуатационную готовность.
Capture сначала вставляет событие, затем тест/решение и связи: ошибка между
операциями может оставить неполную запись. Это приоритетный риск целостности.
Экспорт HTML ограничен первыми 500 событиями. Списки и поиск имеют другие limit.
Защита tenant isolation действует в приложении; RLS нет, исчерпывающего доказательства
всех путей доступа пока нет. Персональные настройки ограничены.
Фотографии обслуживаются приватным endpoint, без публичного image optimizer.

## Что требует внешних credentials

Postgres, постоянное объектное хранилище, почта, Onshape OAuth, внешние webhook,
AI при включении, cron и мониторинг. Одного указания переменной окружения
недостаточно: S3, отправка писем и Sentry ещё не подключены.

## Что TraceLab пока не умеет

PDF с проверкой реального числа страниц и размера; полная локализация EN/RU/KK;
email verification/reset; общий rate limiting; session management; полный
Settings Center; облачное production-хранилище; проверенное восстановление backup;
полная пагинация; браузерная загрузка моделей; автоматический трёхминутный
judge flow с экспортом PDF; полный browser E2E и accessibility audit.

## Технические лимиты

Текущие: фото 15 MiB, sync-body 10 MiB, очередь отправляется ограниченными пачками.
Base64 увеличивает размер: эти пределы ещё не согласованы во всех путях.
Требуемые 3 команды, 50 участников и 2 GiB на команду ещё не объединены в
универсальную серверную систему квот. Нельзя показывать их как обеспеченные гарантии.

## Найденные проблемы по критичности

- P1: нет rate limiting и завершённых account recovery / verification.
- P1: неатомарное сохранение Capture, неполные записи при ошибке.
- P1: локальный диск для production, нет проверенного backup/restore.
- P1: усечение экспорта и неполные списки; PDF не реализован.
- P1: нельзя считать tenant isolation и role matrix полностью проверенными.
- P2: неполная локализация, Settings, мобильные и accessibility проверки.
- P2: демонстрационные записи/illustrations требуют последовательной маркировки.
- Исправлено: известные уязвимости PostCSS/esbuild; четыре lint-предупреждения.

## Результаты

- Production build: проходит с существующим локальным .env.
- lint --max-warnings=0 и typecheck: проходят.
- 34 unit/security/storage + 85 frontend contracts + 36 model tests: проходят.
- Запуск с DATABASE_URL: 42 теста проходят; 7 tenancy tests пропущены после ошибки
  beforeAll: ECONNREFUSED 127.0.0.1:5432. Database suite не пройден.
- npm audit: 0 известных уязвимостей после обновления.
- Drizzle snapshot check без подключения: проходит. Config-based check сообщает
  ошибку AWS Data API credential validation; применение миграций не проверено.
- i18n:audit: не проходит; 1024 кандидата в первом сканировании. Это нижняя оценка:
  скрипт не выявляет все динамические сообщения и не измеряет процент покрытия.
- Browser E2E, мобильные сценарии и screen reader в этой серии не выполнены.
